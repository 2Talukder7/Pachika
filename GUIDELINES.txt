====================================================================
 PACHIKA — SETUP & FILE GUIDE
====================================================================

This explains exactly where every file goes, what it does, and how
to get the project running locally before deploying it.


--------------------------------------------------------------------
1. FOLDER STRUCTURE
--------------------------------------------------------------------

pachika/
│
├── backend/
│   ├── app.py              <- Flask server (main entry point)
│   ├── recipe_engine.py    <- Pure Python logic: scaling, matching
│   ├── requirements.txt    <- Python dependencies list
│   └── data/
│       └── recipes.json    <- Your recipe database
│
├── frontend/
│   ├── index.html          <- The chat page itself
│   ├── style.css           <- All visual styling (maroon/cream theme)
│   └── script.js           <- Chat logic, talks to the Flask API
│
└── GUIDELINES.txt          <- (this file)

Keep backend/ and frontend/ as two separate folders. This mirrors
how they'll eventually be deployed separately (backend on
PythonAnywhere/Render, frontend on Cloudflare Pages).


--------------------------------------------------------------------
2. WHAT GOES WHERE (which code belongs in which file)
--------------------------------------------------------------------

- Anything that touches HTML structure (sidebar, chat bubbles,
  recipe card layout)              -> frontend/index.html

- Anything visual (colors, fonts, spacing, the Alpona-style
  corner patterns, button styling) -> frontend/style.css

- Anything that runs IN THE BROWSER (sending a message, rendering
  the AI's reply, calling the backend API, playing TTS audio)
                                    -> frontend/script.js

- Anything that must run ON THE SERVER and be trusted/reliable
  (talking to the AI API, scaling ingredient amounts, unit
  conversion, looking up recipes)  -> backend/app.py or
                                       backend/recipe_engine.py

- Your actual recipe data (ingredients, steps, timings)
                                    -> backend/data/recipes.json

Rule of thumb: if it's "what the user sees," it's frontend.
If it's "must always be correct," it's backend.


--------------------------------------------------------------------
3. SOFTWARE SETUP (step-by-step)
--------------------------------------------------------------------

STEP 1 — Install Python
    Download Python 3.10+ from python.org and install it.
    Check it worked:  python --version

STEP 2 — Install VS Code
    Download from code.visualstudio.com
    Install these extensions inside VS Code:
        - Python (by Microsoft)
        - Pylance
        - Live Server (by Ritwick Dey) — lets you preview index.html
          instantly with auto-refresh

STEP 3 — Open the project folder in VS Code
    File > Open Folder > select your "pachika" folder

STEP 4 — Create a virtual environment (keeps dependencies isolated)
    Open VS Code's terminal (Ctrl + `) and run:

        cd backend
        python -m venv venv

    Activate it:
        Windows:      venv\Scripts\activate
        Mac/Linux:    source venv/bin/activate

    You'll know it worked because your terminal line will start
    with "(venv)".

STEP 5 — Install backend dependencies
    While inside backend/ with venv active:

        pip install -r requirements.txt

STEP 6 — Run the backend
        python app.py

    You should see something like:
        Running on http://127.0.0.1:5000

    Leave this terminal running.

STEP 7 — Open the frontend
    Right-click frontend/index.html in VS Code and choose
    "Open with Live Server". This opens the chat page in your
    browser, already wired to talk to your local backend.

STEP 8 — Test it
    Type a dish name (e.g. "khichuri recipe for 4 people") in the
    chat box and press send. You should get a structured recipe
    reply from your local backend using the sample recipes.json data.


--------------------------------------------------------------------
4. ADDING YOUR AI API KEY
--------------------------------------------------------------------

Never write your API key directly in app.py. Instead:

1. Create a file named ".env" inside backend/ (already in
   .gitignore below so it won't be uploaded to GitHub by accident).
2. Put this inside it:
        ANTHROPIC_API_KEY=your_key_here
        GOOGLE_TTS_API_KEY=your_key_here
3. Install python-dotenv:  pip install python-dotenv
4. app.py already includes the two lines needed to load it
   (see the top of app.py).


--------------------------------------------------------------------
5. BEFORE YOU PUSH TO GITHUB
--------------------------------------------------------------------

Create a file named ".gitignore" in your project root with:

        venv/
        __pycache__/
        .env
        *.pyc

This keeps your virtual environment, secrets, and cache files out
of your repository.


--------------------------------------------------------------------
6. RUNNING FROM A PENDRIVE / ONE-CLICK STARTUP
--------------------------------------------------------------------

Two helper scripts are included at the project root:

    run.bat   <- double-click on Windows
    run.sh    <- run on Mac/Linux ( ./run.sh )

Each script automatically:
    1. Creates a virtual environment inside backend/ if one
       doesn't already exist on that machine
    2. Installs everything in requirements.txt
    3. Starts the Flask backend
    4. Opens the app in your default browser

This means: copy the whole "pachika" folder onto a pendrive
(EXCLUDING backend/venv/ — see note below), plug it into any
computer that has Python installed, and double-click run.bat
(or run run.sh). No manual setup steps needed on the new machine.

IMPORTANT — do not copy these onto the pendrive:
    - backend/venv/        (rebuilds automatically, don't carry it)
    - backend/__pycache__/ (regenerates automatically)
    - backend/.env          (contains your API keys — carry this
                              separately/securely, not on a pendrive
                              you might lose or lend out)

The ONLY hard requirement on the other computer is that Python
3.10+ is already installed. Everything else, the script handles.
